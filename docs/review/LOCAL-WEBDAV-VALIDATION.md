- 原生首页“换一换”确实发出站点自身 `fresh_type=5, fetch_row=1` 请求，HTTP 200；旧推荐节点全部断开，按钮恢复可用。没有额外补拉推荐请求。
- 1920/1280 宽度下检查原生骨架布局，保留站点自己的卡片、样式、锚点和滚动加载，不引入 BewlyCat UI。
- 延迟站点原生推荐响应 2.5 秒，并只在测试响应中给一个视频加必命中的测试标题：3357 个加载画面样本中没有内部空白格或该标题闪现；命中项在响应数据层剔除。测试没有创建补充 B 站请求。
- 原站自身可能对慢响应提前超时，因此该慢网测试证明“不泄漏被屏蔽项、不中断原有骨架”，不把超时后的首屏保留项误记为延迟响应已完整渲染。
- 单独模拟 DOM 卡片复用：先隐藏命中视频，再把同一节点换成原生 skeleton，本插件的隐藏/已处理/屏蔽标记均恢复，骨架可见。
- 测试期间脚本运行错误为 0，补充 B 站 GM 请求为 0。慢响应自检等待条件另有单测，真实失败仍保留告警。

## WebDAV 界面与真实 HTTP 协议验证

使用自建的仅本机内存 WebDAV 测试服务及虚构凭据，在真实浏览器中运行面板、浏览器原生 DOMParser 和 PROPFIND/MKCOL/GET/PUT。没有连接或改动用户云端文件。

- 三个带标签输入：仓库目录地址、用户名、密钥；打开面板和保存设置不联网。
- Depth 1 自动发现 `PiliNara/` 中 phone/desktop 两份设备配置；多个文件未选择时阻止读写，选中 phone 后 desktop 保持原样。
- 自动创建 `biliHoyoFairy-MX703/`，写入 `config.json`；重复备份的 MKCOL 405 通过 Depth 0 验证目录后成功写入。
- PiliNara 读取合并保留本地原 UID；写入采用 GET→去重追加→带 `If-Match` 的 PUT，保留远端已有名字及其他设置。再次合并没有新增项时仅 GET、不 PUT。
- JSON 文本定位的独立单测验证旧推荐名单原文本、原顺序、非标准但合法的 UID 键和未知项均保留，新 UID 只在末尾追加。
- 备份没有 WebDAV 凭据、元数据缓存、运行统计和本机补充取数授权；修改测试云备份为 `allowMetadataRequests:true` 后恢复，规则可恢复而本机授权仍保持关闭。
- 测试 WebDAV 流程期间额外 B 站 GM 请求为 0。
