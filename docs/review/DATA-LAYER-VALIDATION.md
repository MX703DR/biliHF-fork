# 渲染前过滤与首页完整刷新验证

验证日期：2026-10-03；待发布脚本版本：0.0.9。

## 实现范围

推荐、热门、排行、搜索、相关推荐和动态的 fetch/XHR 响应，在交还页面前完成本地与按需元数据判定，并一次删掉命中项。首页和搜索 SSR 先判定、暂缓内容显示，待原生 hydrate 完成后通过实际 Pinia store 提交；搜索 shallowRef 重赋根对象以触发更新，列表顺序和原始分页仍保留。

评论隐藏模式直接过滤主列表、置顶及子回复数据；折叠和审查模式保留原文，以便展开/核对。没有可拦截数据源的第三方卡片仍保留绘制前 DOM 兜底。修改已显示视频的规则时不先恢复全部隐藏项，只有必要的显隐变化造成补位。

精确过滤沿用缓存、3 并发、限速及风控熔断，整批等待最多 8 秒。超时后临时放行，本批迟到结果不再挪走已经显示的视频；下一批可重新判定。SSR 接管失败会在 8.5 秒内解除临时可见性闸门。

首页原“换一换”调用 B站现有的完整刷新入口，不引入第三方 UI。原生签名和访客参数不改，旧分页响应不能回填新列表；入口缺失时降级为整页刷新。

## 自动验证

`npm run typecheck`、`npm run lint`、`npm test`、`npm run build` 均通过，31 个测试文件、450 项测试。测试覆盖异步元数据、规则版本变化、白名单优先、超时/熔断、请求取消、XHR 复用及事件顺序、fetch clone 元数据、SSR 接管/shallowRef、视频搜索同页回放/参数变化/恢复 action、搜索内嵌预览、评论置顶双副本、合法空列表与健康检查。

## 实际 B站游客模式验证

使用独立的 Chrome 游客会话，在 document-start 注入当前源码构建，GM 存储用隔离内存垫片，元数据请求访问真实 B站接口。没有登录、写账号黑名单或修改用户原有配置。除旧分页竞态测试有意延迟真实响应外，没有替换站点数据。

- 首页：真实标签接口返回 code 0，命中“游戏”标签的视频未进入可见列表；逐帧记录未发现被拦内容闪现。过滤后逐一核对原生 store 与卡片标题、BV 链接一致。
- 完整刷新：先滚动加载下方推荐，再点击原“换一换”。真实请求为 `fresh_type=5, fetch_row=1`，HTTP 200、code 0，保留 `w_rid`；已加载的旧下方节点全部断开，滚动回顶部，按钮恢复可用。
- 旧请求竞态：将真实的旧 `fetch_row=4` 响应延迟 1600ms，期间完整刷新；旧批次没有追加回新列表。
- 综合搜索“原神”：普通结果与用户卡片投稿预览一起过滤，保留用户卡片；最终可见卡片与状态逐一一致，命中项没有残留为隐藏卡片，也没有逐帧闪现。实测修复了 hydrate 前删快照引起的标题/链接错位，以及 shallowRef 嵌套修改不触发渲染的问题。
- 视频搜索标签页：组件会另存一份转换后的本地列表。通过原生 `submitSearch` 控制器一次性回放已过滤的同页 SSR 数据，同步这份副本；仅同查询、同页、同配置版本可回放，之后立即恢复原生 action，未增加搜索请求。结合真实标签接口验证，最终 store 与 DOM 视频顺序一致，没有残留隐藏卡片或逐帧闪现。
- 搜索翻页：综合搜索和视频搜索均实际点击第 2 页，真实 WBI 请求 HTTP 200。视频搜索回放后的翻页仍走原生请求，第 2 页状态与 5 张保留卡片逐一一致；新卡片数据层过滤，保留项顺序稳定，没有 DOM 补隐藏或逐帧闪现。
- 已显示视频：右键选择“屏蔽此视频”，只隐藏选中的 BV，其余视频顺序逐一保持不变。
- 热门页：真实推荐列表已在数据中删去命中项，保留项正常显示，没有二次 DOM 隐藏或逐帧闪现。
- [示例视频评论](https://www.bilibili.com/video/BV17dbV65EJt/)：隐藏模式下，命中的置顶子回复和普通子回复未创建评论宿主；UP 的置顶原文与其他回复保留。折叠模式创建两条折叠条，原文未先闪现，实际点击可以展开再收起。

游客视频页面存在 B站原生 reporter/telemetry 资源失败及访客登录提示；未注入脚本时也存在同类问题。已关闭登录提示后完成折叠点击验证，未将这些资源错误当作插件错误。登录态专属接口和第三方 UI 扩展未在此次游客会话运行，相关规则/响应结构以自动测试覆盖。
